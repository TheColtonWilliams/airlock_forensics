# Commands

Every command installed on the AIRLOCK image, one line each: what it does and where it comes from.

* `airlock-setro NAME | --all | --check` (`/usr/local/sbin`, role `harden_storage`, task 3.2): applies the software read-only policy (`blockdev --setro`) to a disk or partition that is not on the boot disk and logs the decision; udev runs it for every new disk; `--check` lists each disk's state and fails if one that should be read-only is writable.
* `forensic-analyze` (`/usr/local/bin`, role `session_tools`, tasks 4C.1-4C.4, 4C.16-4C.20, 4C.22-4C.26, 3A.5-3A.7, 3A.9): the guided analysis wizard; asks for authority, case fields, clock reference, write-blocker answer, target, mode, output, and preset (every question has a flag), runs the modules sandboxed with a write tracer and before/after hashes, and writes a signed run folder; `--resume`, `--config run.json`, `--verify RUN_DIR`, `--purge-run RUN_DIR`, `--dry-run`. See `docs/workflows/guided-analysis.md`.
* `airlock-firstboot` (`/opt/airlock/libexec`, role `base`, task 1.10): run once by `airlock-firstboot.service` on a new drive; commits a new machine ID, grows the root partition and filesystem to the drive, disables itself.
* `airlock-partition-layout [--check | --format-empty] [--json]` (`/opt/airlock/libexec`, role `base`, tasks 2B.9, 2B.17): checks or sets the GPT names and types of the five AIRLOCK partitions on the disk holding `/`; `--format-empty` makes exFAT on an empty ASSETS or OUTPUT; never touches another disk or reformats.
* `airlock-install-bootloader [--targets efi,bios]` (`/opt/airlock/libexec`, role `base`, task 1.9): installs the signed UEFI loader at the removable path (no NVRAM entry) and the BIOS loader on the disk holding `/boot`.
* `airlock-check-boot-chain --min-sbat COMP=GEN FILE...` (`/opt/airlock/libexec`, role `base`, task 1.13): prints SBAT levels and signers of EFI binaries as JSON; exit 1 below the minimum.
* `ai-probe [--json] [--write] [--vulkaninfo FILE] [--meminfo FILE] [--no-model-check]` (`/usr/local/bin`, code `airlock_ai.probe`, task 4B.3): picks the local model tier from the largest device-local Vulkan heap (integrated GPUs capped at RAM minus a margin), never from the vendor; tier0 on the CPU when there is no GPU; `--write` (run at boot by `airlock-ai-probe.service`) saves `/var/lib/airlock/ai-tier.json`.
* `evidence-screen FILES|FOLDERS -o screen.csv [-r] [--thresholds FILE]` (`/usr/local/bin`, code `airlock_ai.screen`, tasks 4B.6, 4B.7): scores images and video frames with NudeNet and SigLIP in a sandbox with no network and writes verdicts, scores, thresholds, and model hashes; never shows a file. See `docs/workflows/media-screening.md`.
* `evidence-describe FILES -o describe.csv --screen-csv screen.csv [--no-start]` (`/usr/local/bin`, code `airlock_ai.describe`, tasks 4B.7-4B.9): AI-generated descriptions of cleared images and videos, and summaries of documents and audio transcripts, from the local model on 127.0.0.1; refusals are `model_declined`, never dropped.
* `evidence-report RUN_DIR [--no-model] [--model-url URL] [--no-start] [--seed N] [--data-chars N] [--max-calls N] [--no-resign]` (`/usr/local/bin`, code `evidence_report`, tasks 4B.11, 4E.1-4E.11): writes `report.html` and `report.md` for a run; code fills the factual sections, the local model on 127.0.0.1 drafts results, interpretation, and conclusions from `case.sqlite` view rows with fixed hashed prompts, and a code verifier removes every sentence it cannot match to the findings it cites. Called by `forensic-analyze` before hashing and signing; run by hand it re-signs the folder. See `docs/workflows/report.md`.
* `forensic-escalate [--run RUN_DIR] [--finding ID] [--path PATH] [--sha256 HASH] [--yes]` (`/usr/local/bin`, code `airlock_ai.escalate`, task 4B.18): stop control for suspected illegal material; halts `forensic-analyze`, freezes exports, records only path, finding ID, and hash, and shows the contact-law-enforcement guidance. Never opens the file.
* `airlock-llama-serve` (`python3 -m airlock_ai.serve`, run by `llama-server.service`, task 4B.10): starts `/opt/llama/bin/llama-server` on 127.0.0.1 with the probed tier, falls back to the CPU tier if the GPU tier fails to load, records model hashes in `/run/airlock-llama/effective.json`.
* `forensic-session-start [--authority-ack] [--clock-ok | --reference-time ISO [--reference-source TEXT]] [--write-blocker yes|no|unknown] [--blocker-model TEXT] [--quick-asset-check] [--yes] [--pause-at-end]` (`/usr/local/bin`, code `airlock_session.start`, tasks 4.10, 4.11, 4.15, 4F.6, 2B.14, 4C.22, risk 14): runs at login; starts a new session log, asks for the authority acknowledgement, the clock check (logs the offset, never sets the clock), and whether a hardware write blocker is used, then records kernel, tool versions, `lsblk`, read-only flags, radios, network, image age (warns past 90 days), and the ASSETS hash check. See `docs/workflows/session.md`.
* `evidence-unlock-output /dev/sdX [--confirm NAME] [--lock]` (`/usr/local/bin`, code `airlock_session.unlock`, task 4.10): makes one whole drive writable for case output after you type its name back; refuses the AIRLOCK drive and partitions; logs model, serial, and size (logging is not enforcement); `--lock` makes it read-only again.
* `evidence-mount IMAGE [MOUNTPOINT] [--partition N] | --unmount TARGET | --list` (`/usr/local/bin`, code `airlock_session.mount`, tasks 3A.3, 4.10): mounts an image file (never a drive) through a read-only loop device with `ro,noexec,nosuid,nodev` plus `noload`/`norecovery`; NTFS via `ntfs-3g` read-only; warns that mounting exposes kernel parsers; hashes before, after mounting, and after unmounting, and fails loudly on a change.
* `evidence-hash TARGET [--sha1] [--json]` (`/usr/local/bin`, code `airlock_session.hashcmd`, task 4.10): SHA-256 and MD5 (and SHA-1) of a drive or image in one read-only pass, appended to the session log.
* `evidence-triage TARGET [--no-hash] [--no-dissect] [--timeout S] [--json]` (`/usr/local/bin`, code `airlock_session.triage`, task 4.10): runs `mmls`, `fsstat` per partition, the evidence hash, and Dissect `target-info`, all read-only, and writes each result to the session log; a missing tool is logged as `tool_missing`.
* `evidence-triage-hash FOLDERS|FILES | --list FILE -o OUT.csv [--quiet] [--no-sandbox]` (`/usr/local/bin`, code `airlock_hashsets.triage`, tasks 4A.6, 4D.8): MD5, SHA-1, SHA-256 of every file in one read-only pass; drops NSRL known software (SHA-256 first, algorithm recorded); flags ClamAV, MalwareBazaar (`.hsb`), YARA, and ssdeep matches (fuzzy marked inferred); writes a spreadsheet-safe CSV (never inside the input folder) and the counts to the session log. See `docs/workflows/hash-triage.md`.
* `python3 -m airlock_hashsets.build mbz-hsb|clamav|yara|nsrl|check` (code `airlock_hashsets.build`, run by role `tools_hashsets` at provisioning, tasks 4A.2-4A.5, 4A.8): converts MalwareBazaar to a ClamAV `.hsb`, checks ClamAV databases with `sigtool`, compiles YARA packs, extracts NSRL; `check` confirms every staged set is present and loads (goss).
* `forensic-provision [--if-changed] [--no-reboot] [--restart]` (`/usr/local/bin`, code `airlock_provision`, tasks 2B.4-2B.7, 2B.12, 2B.15): sets the drive up offline from ASSETS: refuses while a network interface is up, a default route exists, or another disk is attached; checks every staged file against the signed manifest, turns off features whose files are missing or damaged, runs the Ansible roles locally, runs goss, writes `/var/lib/airlock/provision-manifest.json`, reboots; checkpointed per step, so it resumes after a power cut. Run at boot by `airlock-provision.service` with `--if-changed`. See `docs/assets.md`.
* `forensic-import [--dry-run] [--force]` (`/usr/local/bin`, code `airlock_provision`, task 4A.7): checks and applies hash sets, signatures, and models restaged with `fetch-assets --refresh`, offline, and logs every file's old and new SHA-256; refuses while an evidence disk is attached.
* `python3 -m airlock_common.assets verify [--quick] [--json] [--log-tool NAME]` (code `airlock_common.assets`, tasks 2B.14, 4G.4): checks the staged ASSETS files against the trusted manifest (SHA-256 of every file, or presence and size with `--quick`), names each problem and the feature it turns off, exit 1 on a problem.
